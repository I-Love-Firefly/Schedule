# DeepSeek API 课程表识别

## 运行顺序

1. Android 端先运行设备 OCR，得到文字块和归一化坐标，作为模型提示和结果校验证据。
2. APP 通过 HTTPS 将完整图片和 OCR 坐标发送到自有网关。
3. 网关调用 DeepSeek 官方 `deepseek-v4-flash-vision-exp` 视觉模型，将课程表结构化为固定 JSON。
4. 视觉模型暂不可用时，网关可调用 DeepSeek 文本模型处理 OCR 坐标；两条路径都属于服务器 API 识别。
5. API、网络或服务器不可用时，APP 直接显示失败且不写入数据库，不存在设备端模型或本地识别回退。
6. API JSON 必须经过客户端字段、OCR 证据、时间和网格校验；未通过质量闸门的结果只能在用户逐项确认后写库。

## 密钥边界

- DeepSeek API Key 只存放在服务器的 `Server/ScheduleAiGateway/.env`。
- `.env` 已加入 `.gitignore`，不得复制到客户端资源、源码、日志或 GitHub。
- APP 只知道自有 HTTPS 网关地址，不知道 DeepSeek API Key。
- Key 应设置用量告警、费用上限和轮换周期；一旦在聊天、终端历史或日志中暴露，应立即作废并更换。

## 数据处理

网关不主动持久化图片和 OCR 内容，正常日志只记录请求 ID、模型名和耗时。APP 在隐私政策和导入页面明确提示：课程表图片会传至开发者运营的网关和 DeepSeek API，课程数据库仍只保存在设备本地。

公网发布前仍需补充正式的用户身份认证或 Android 应用完整性校验。当前网关的 IP 限流和每日总限额主要用于内测及成本兜底，不能替代生产身份认证。
